# Сети: OSI и TCP/IP

## Зачем это нужно

Сети — фундамент всей инфраструктуры. Без понимания моделей OSI и TCP/IP
невозможно диагностировать проблемы: «сайт не открывается», «пинг идёт,
а сервис не отвечает», «пакеты теряются». На собесе это база, спрашивают
почти всегда.

## Модель OSI — 7 уровней

**OSI (Open Systems Interconnection)** — эталонная модель, описывающая,
как данные передаются по сети. 7 уровней, снизу вверх:

| №   | Уровень                          | Что делает                  | Примеры                    |
| --- | -------------------------------- | --------------------------- | -------------------------- |
| 7   | **Прикладной** (Application)     | Интерфейс для приложений    | HTTP, FTP, DNS, SMTP       |
| 6   | **Представления** (Presentation) | Формат данных, шифрование   | TLS, JPEG, ASCII           |
| 5   | **Сеансовый** (Session)          | Управление сессиями         | RPC, NetBIOS               |
| 4   | **Транспортный** (Transport)     | Доставка, порты, надёжность | TCP, UDP                   |
| 3   | **Сетевой** (Network)            | Маршрутизация, IP-адреса    | IP, ICMP, OSPF             |
| 2   | **Канальный** (Data Link)        | MAC-адреса, кадры           | Ethernet, Wi-Fi, ARP       |
| 1   | **Физический** (Physical)        | Кабели, сигналы, биты       | Кабель, оптоволокно, радио |

**Мнемоника (снизу вверх):** «Physical, Data, Network, Transport, Session,
Presentation, Application» → **P**lease **D**o **N**ot **T**hrow **S**ausage
**P**izza **A**way.

**Мнемоника (сверху вниз, по-русски):** «Прикладной, Представления,
Сеансовый, Транспортный, Сетевой, Канальный, Физический» → **П**ришёл
**П**осмотреть **С**ериал, **Т**олько **С**ети **К**абельные **Ф**изика.

### Как данные идут по уровням

Отправитель (сверху вниз) Получатель (снизу вверх)
───────────────────────── ─────────────────────────

Application 7. Application

Presentation 6. Presentation

Session 5. Session

Transport (TCP/UDP) 4. Transport

Network (IP) 3. Network

Data Link (MAC) 2. Data Link

Physical ───── сигнал ────> 1. Physical


**Инкапсуляция:** на каждом уровне к данным добавляется свой заголовок.
Когда данные доходят до получателя — заголовки снимаются в обратном порядке
(**декапсуляция**).

## Модель TCP/IP — 4 уровня

**TCP/IP** — практическая модель, по которой реально работает интернет.
Проще OSI, 4 уровня:

| №   | Уровень                      | Соответствие в OSI | Примеры             |
| --- | ---------------------------- | ------------------ | ------------------- |
| 4   | **Прикладной** (Application) | OSI 5+6+7          | HTTP, DNS, SSH, FTP |
| 3   | **Транспортный** (Transport) | OSI 4              | TCP, UDP            |
| 2   | **Межсетевой** (Internet)    | OSI 3              | IP, ICMP, ARP       |
| 1   | **Канальный** (Link)         | OSI 1+2            | Ethernet, Wi-Fi     |

**Разница:** TCP/IP — практическая модель, по которой строятся реальные
протоколы. OSI — эталонная, используется для обучения и описания.

## Ключевые протоколы по уровням

### Прикладной уровень (Application)
- **HTTP/HTTPS** — веб (80/443).
- **DNS** — резолв имён (53).
- **DHCP** — выдача IP (67/68).
- **SMTP/IMAP/POP3** — почта (25/143/110).
- **SSH** — удалённый доступ (22).
- **RDP** — удалённый рабочий стол (3389).
- **SMB** — файловые шары Windows (445).

### Транспортный уровень (Transport)
- **TCP** — надёжный, с установкой соединения (handshake).
- **UDP** — быстрый, без гарантий доставки.

### Межсетевой уровень (Internet)
- **IP** — адресация и маршрутизация.
- **ICMP** — диагностика (ping, traceroute).
- **ARP** — сопоставление IP ↔ MAC.

### Канальный уровень (Link)
- **Ethernet** — проводная сеть.
- **Wi-Fi (802.11)** — беспроводная.

## TCP vs UDP

| Характеристика | TCP                          | UDP                    |
| -------------- | ---------------------------- | ---------------------- |
| Соединение     | Устанавливается (handshake)  | Нет                    |
| Надёжность     | Гарантирована доставка       | Не гарантирована       |
| Порядок        | Пакеты собираются по порядку | Может быть любой       |
| Скорость       | Медленнее                    | Быстрее                |
| Применение     | HTTP, SSH, SMB, RDP          | DNS, VoIP, видео, игры |

**TCP-соединение устанавливается через 3-way handshake:**

Клиент → SYN → Сервер
Клиент ← SYN-ACK ← Сервер
Клиент → ACK → Сервер
Соединение установлено

**Завершение — 4-way:**
FIN → ← ACK → ← FIN → ACK



## Что важно не путать

- **OSI ≠ TCP/IP.** OSI — эталон, TCP/IP — практика.
- **IP-адрес ≠ MAC-адрес.** IP — уровень 3, меняется при маршрутизации.
  MAC — уровень 2, не меняется в пределах сегмента.
- **TCP ≠ IP.** TCP — транспорт, IP — сеть. Работают вместе: TCP/IP.
- **Порт ≠ протокол.** Порт — номер (80, 443), протокол — HTTP, HTTPS.
