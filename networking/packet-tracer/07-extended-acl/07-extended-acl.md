# 07. Extended ACL

## Задача

Настроить Extended ACL, чтобы PC0 (сеть A) не мог открыть веб-сервер
(порт 80) в сети B. Всё остальное — разрешено.

## Что понадобилось

- **Cisco Packet Tracer**
- **Устройства:** 2 PC, 2 Switch (2960), 2 Router (2911), 1 Server
- **Время:** ~30 минут

## Топология

PC0 ─┐
├── Switch0 ── Router0 ── Router1 ── Switch1 ── Server1
PC2 ─┘ G0/1 G0/0 G0/0 G0/1
192.168.1.1 10.0.0.1 10.0.0.2 192.168.3.1
сеть A: 192.168.1.0/24 сеть B: 192.168.3.0/24


**Сети:**
- **Сеть A** (за Router0): `192.168.1.0/24`.
- **Сеть B** (за Router1): `192.168.3.0/24`.
- **Link** между роутерами: `10.0.0.0/30`.

## Настройки

| Устройство | Интерфейс | IP           | Маска | Шлюз        |
| ---------- | --------- | ------------ | ----- | ----------- |
| PC0        | NIC       | 192.168.1.10 | /24   | 192.168.1.1 |
| PC2        | NIC       | 192.168.1.20 | /24   | 192.168.1.1 |
| Router0    | G0/1      | 192.168.1.1  | /24   | —           |
| Router0    | G0/0      | 10.0.0.1     | /30   | —           |
| Router1    | G0/0      | 10.0.0.2     | /30   | —           |
| Router1    | G0/1      | 192.168.3.1  | /24   | —           |
| Server1    | NIC       | 192.168.3.10 | /24   | 192.168.3.1 |

**Маршруты** — как в лабе 05:
- Router0: `ip route 192.168.3.0 255.255.255.0 10.0.0.2`
- Router1: `ip route 192.168.1.0 255.255.255.0 10.0.0.1`

## Ход работы

1. Собрал топологию: 2 роутера, 2 коммутатора, PC0, PC2, Server1.
2. Настроил IP и маршруты (как в лабе 05).
3. Настроил веб-сервер на Server1 (HTTP включён по умолчанию).
4. Создал Extended ACL 100 на Router0.
5. Привязал ACL к интерфейсу `G0/1` в направлении `in`.
6. Проверил `show access-lists` — счётчики.
7. Проверил PC0 → Server1 (HTTP) — Request Timeout.
8. Проверил PC0 → Server1 (ping) — работает.
9. Проверил PC2 → Server1 (HTTP) — Request Timeout.

## Команды / настройки

### На Router0
```
enable
configure terminal

! Extended ACL
access-list 100 deny tcp 192.168.1.0 0.0.0.255 host 192.168.3.10 eq 80
access-list 100 permit ip any any

! Привязка ACL к интерфейсу
interface Gig0/1
ip access-group 100 in
exit

exit
write memory
```


**Разбор:**

- **`access-list 100`** — extended ACL (номер 100–199).
- **`deny tcp`** — запретить TCP.
- **`192.168.1.0 0.0.0.255`** — источник (сеть A, wildcard).
- **`host 192.168.3.10`** — назначение (Server1). `host` = `/32`.
- **`eq 80`** — порт 80 (HTTP). Можно писать `eq www`.
- **`permit ip any any`** — разрешить всё остальное.
- **`ip access-group 100 in`** — применить ACL на **входящий** трафик `G0/1`.

**Почему `in` на `G0/1`:** ACL применяется на входе — трафик от PC0 проверяется **до** маршрутизации. Это **ближе к источнику**.

### Проверка на Router0

`show access-lists`


Ожидаемый вывод:
```
Extended IP access list 100
10 deny tcp 192.168.1.0 0.0.0.255 host 192.168.3.10 eq www (N match(es))
20 permit ip any any (M match(es))
```


- **N matches** — сколько пакетов заблокировано.
- **M matches** — сколько пропущено.

`show ip interface Gig0/1`


Должно быть:

`Inbound access list is 100`


### Проверка с PC0

**PC0 → Server1 (HTTP):**
- Открыть **Desktop → Web Browser**.
- Ввести: `http://192.168.3.10`.
- Результат: **Request Timeout** ❌

**PC0 → Server1 (ping):**

`ping 192.168.3.10`

Результат: **0% потерь, TTL=126** ✅

**ACL блокирует TCP:80, но пропускает ICMP.**

## Результат

| Проверка                 | Результат                          |
| ------------------------ | ---------------------------------- |
| PC0 → Server1 (HTTP)     | Request Timeout                    |
| PC2 → Server1 (HTTP)     | Request Timeout                    |
| PC0 → Server1 (ping)     | Ping OK, TTL=126                   |
| `show access-lists`      | deny: N matches, permit: M matches |
| `show ip interface G0/1` | Inbound access list is 100         |

**Extended ACL работает** — блокирует TCP:80 из сети A, пропускает всё остальное.

## Грабли

- **Двойной `http://` в URL** — «Protocol Not Supported». Вводить `http://192.168.3.10` (один раз).
- **ACL без привязки к интерфейсу** — не работает.
- **Счётчик deny = 0**, если трафик не идёт через интерфейс.
- **Забыл `permit ip any any`** — неявный `deny any` заблокирует весь остальной трафик.
- **Неправильное направление (`in`/`out`)** — ACL применяется не к тому трафику.

## Что запомнить

- **ACL** — список правил permit/deny для фильтрации трафика.
- **Standard ACL** — только источник. **Extended** — источник, назначение, протокол, порты.
- **Правила обрабатываются сверху вниз**, первое совпадение выигрывает.
- **В конце ACL неявный `deny any`** — всё, что не разрешено, запрещено.
- **Wildcard mask** = инверсия обычной маски (`255.255.255.0` → `0.0.0.255`).
- **`host <IP>`** = `/32`, **`any`** = любой адрес.
- **`ip access-group <номер> in/out`** — привязка ACL к интерфейсу.
- **`in`** — на входе (до маршрутизации), **`out`** — на выходе.
- **`show access-lists`** — счётчики совпадений.
- **ACL блокирует конкретный протокол/порт**, не весь трафик.
- **Standard ACL — ближе к назначению, Extended — ближе к источнику.**
