# 05. Статическая маршрутизация

## Задача

Собрать сеть из 2 роутеров, соединённых link-ом. Настроить
статические маршруты, чтобы PC0 (сеть A) пинговал PC1 (сеть B).

## Что понадобилось

- **Cisco Packet Tracer**
- **Устройства:** 2 PC, 2 Switch (2960), 2 Router (2911)
- **Время:** ~30 минут

## Топология
PC0 ── Switch0 ── Router0 ── Router1 ── Switch1 ── PC1
сеть A G0/1 G0/0 G0/0 G0/1 сеть B
192.168.1.1 10.0.0.1 10.0.0.2 192.168.3.1
link: 10.0.0.0/30


**Сети:**
- **Сеть A** (за Router0): `192.168.1.0/24`, шлюз `192.168.1.1`.
- **Сеть B** (за Router1): `192.168.3.0/24`, шлюз `192.168.3.1`.
- **Link** между роутерами: `10.0.0.0/30`.
  - Router0 `G0/0`: `10.0.0.1/30`.
  - Router1 `G0/0`: `10.0.0.2/30`.

**Почему `/30`:** между двумя роутерами нужны только 2 адреса. `/30` даёт ровно 2 хоста — минимум для point-to-point.

## Настройки

| Устройство | Интерфейс | IP           | Маска | Шлюз        |
| ---------- | --------- | ------------ | ----- | ----------- |
| PC0        | NIC       | 192.168.1.10 | /24   | 192.168.1.1 |
| PC1        | NIC       | 192.168.3.10 | /24   | 192.168.3.1 |
| Router0    | G0/1      | 192.168.1.1  | /24   | —           |
| Router0    | G0/0      | 10.0.0.1     | /30   | —           |
| Router1    | G0/0      | 10.0.0.2     | /30   | —           |
| Router1    | G0/1      | 192.168.3.1  | /24   | —           |

## Ход работы

1. Собрал топологию: 2 роутера, 2 коммутатора, 2 ПК.
2. Настроил IP на всех интерфейсах.
3. Поднял интерфейсы (`no shutdown`).
4. Проверил `show ip route` — только connected маршруты.
5. Добавил статические маршруты на обоих роутерах.
6. Проверил `show ip route` — появились `S` маршруты.
7. Проверил ping PC0 → PC1 — работает, TTL=126.
8. Проверил tracert — путь через 2 роутера.

## Команды / настройки

### На Router0
```
enable
configure terminal

interface Gig0/0
ip address 10.0.0.1 255.255.255.252
no shutdown
exit

interface Gig0/1
ip address 192.168.1.1 255.255.255.0
no shutdown
exit

! Статический маршрут к сети B через Router1
ip route 192.168.3.0 255.255.255.0 10.0.0.2

exit
write memory
```
### На Router1
```
enable
configure terminal

interface Gig0/0
ip address 10.0.0.2 255.255.255.252
no shutdown
exit

interface Gig0/1
ip address 192.168.3.1 255.255.255.0
no shutdown
exit

! Статический маршрут к сети A через Router0
ip route 192.168.1.0 255.255.255.0 10.0.0.1

exit
write memory
```

### Проверка на Router0

`show ip route`

Ожидаемый вывод:
```
C 10.0.0.0/30 is directly connected, GigabitEthernet0/0
L 10.0.0.1/32 is directly connected, GigabitEthernet0/0
C 192.168.1.0/24 is directly connected, GigabitEthernet0/1
L 192.168.1.1/32 is directly connected, GigabitEthernet0/1
S 192.168.3.0/24 [1/0] via 10.0.0.2
```


**`S`** — статический маршрут. Router0 знает: «сеть B — через `10.0.0.2`».

### Проверка с PC0

**PC0 → PC1:**

`ping 192.168.3.10`

Результат: **0% потерь, TTL=126** ✅

**tracert:**

`tracert 192.168.3.10`

Результат:

1. 192.168.1.1 (Router0)

2. 10.0.0.2 (Router1)

3. 192.168.3.10 (PC1)
Trace complete.


## Результат

| Ping                       | TTL | Хопов |
| -------------------------- | --- | ----- |
| PC0 → 192.168.1.1 (шлюз)   | 255 | 0     |
| PC0 → 10.0.0.2 (Router1)   | 254 | 1     |
| PC0 → 192.168.3.1 (шлюз B) | 254 | 1     |
| PC0 → 192.168.3.10 (PC1)   | 126 | 2     |

**TTL уменьшается на 1 на каждом роутере** — доказательство маршрутизации.
**tracert** показывает путь через 2 роутера.

## Грабли

- **Забыл `no shutdown`** — интерфейсы в статусе `administratively down`.
- **Забыл IP** — интерфейсы `unassigned`, connected маршрутов нет.
- **Неправильный next-hop** — маршрут есть, но не работает.
- **Шлюз на ПК не настроен** — ПК не знает, куда отправлять пакеты за пределы подсети.
- **Кабели подключены не к тем интерфейсам** — `show cdp neighbors` помогает.
- **CDP-таблица кэшируется** — `clear cdp table` для актуальных соседей.
- **`show cdp neighbors`** показывает физику, `show cdp neighbors detail` — ещё и IP соседей.

## Что запомнить

- **Connected-маршруты (`C`)** — автоматически для подключённых сетей.
- **Статические маршруты (`S`)** — вручную для удалённых сетей.
- **`ip route <сеть> <маска> <next-hop>`** — синтаксис.
- **TTL уменьшается на 1** на каждом роутере.
- **`/30`** — маска для point-to-point link (2 адреса).
- **`tracert`** — показывает путь пакета через роутеры.
- **Статические маршруты не масштабируются** — для больших сетей нужен OSPF.
