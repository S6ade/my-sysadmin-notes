# 00. Обзор практики по Windows Server + Active Directory

Краткое описание всей темы — от поднятия контроллера домена до применения
групповых политик. Детали — в отдельных файлах практики.

## Что делали

Развернули полноценную инфраструктуру AD: контроллер домена, клиент,
структура OU, пользователи, группы, права доступа, групповые политики.

## Пошаговый обзор

### 1. Контроллер домена (DC)
- Создали VM `DC01` с Windows Server 2025 (Desktop Experience).
- Задали статический IP `10.10.10.10/24`.
- Указали DNS-сервером сам себя — критично для AD.
- Установили роли **AD DS** и **DNS**.
- Создали новый лес `company.local`.
- Проверили: AD Users and Computers, DNS-зона, SRV-запись
  `_ldap._tcp.dc._msdcs.company.local`.

**Детали:** [01-dc-setup.md](01-dc-setup.md)

### 2. Структура AD: OU, пользователи, группы, AGDLP
- Создали 3 OU в корне домена: `Отдел продаж`, `Бухгалтерия`, `IT`.
- В каждой — подпапки `Пользователи` и `Компьютеры`.
- Завели 6 пользователей (по 2 в каждой OU).
- Создали 3 глобальные группы безопасности: `GG_IT`, `GG_Отдел_продаж`,
  `GG_Бухгалтерия`.
- Создали доменную локальную группу `DL_Shared_RW`.
- Прошли схему **AGDLP**:
  - `ismirnov` → `GG_IT` → `DL_Shared_RW` → Modify на `C:\Shared`.
  - `ppetrov` → `GG_Отдел_продаж` → `DL_Shared_RW` → Modify.
  - `iivanova` → `GG_Бухгалтерия` → не в DL → **нет доступа**.
- Настроили права Share + NTFS, проверили через Effective Access.

**Детали:** [02-ou-users-groups.md](02-ou-users-groups.md)

### 3. Клиент Windows и ввод в домен
- Создали VM `client01` с Windows 11 Pro.
- Подключили к той же сети, что DC.
- Задали статический IP `10.10.10.20/24` и **DNS = `10.10.10.10`** (IP DC).
- Проверили связность: `ping`, `nslookup company.local`,
  `nslookup -type=SRV _ldap._tcp.dc._msdcs.company.local`.
- Ввели клиент в домен `company.local` через `sysdm.cpl`.
- Учётка компьютера `CLIENT01` появилась в AD автоматически.
- Вошли под доменным пользователем `COMPANY\ismirnov`.
- Проверили: `whoami` → `company\ismirnov`.

### 4. Групповые политики (GPO)
- На DC в `gpmc.msc` создали GPO `GPO_Запрет_Панели_Управления`.
- Привязали к OU **`Отдел продаж`** (не к группе, не к DC).
- Включили политику «Запретить доступ к панели управления и параметрам
  компьютера» (Конфигурация пользователя).
- На client01 под `ppetrov` (Отдел продаж):
  - `gpupdate /force` → GPO применена.
  - `gpresult /r` → GPO в списке применённых.
  - `control` → заблокировано.
- На client01 под `iivanova` (Бухгалтерия):
  - `control` → открывается.
  - `gpresult /r` → GPO **не применена**.

**Детали:** [03-gpo.md](03-gpo.md)

## Ключевые принципы, которые подтверждены на практике

- **AD без DNS не работает** — клиент находит DC через SRV-записи.
- **DNS клиента = IP DC** — обязательное условие входа в домен.
- **Права дают группам, а не пользователям** — через схему AGDLP.
- **GPO привязывается к OU**, а не к группе или серверу.
- **GPO применяется избирательно** — по структуре OU.

## Команды, которые использовали

| Команда                                                 | Назначение                    |
| ------------------------------------------------------- | ----------------------------- |
| `ipconfig /all`                                         | Проверка IP и DNS             |
| `nslookup company.local`                                | Проверка резолва домена       |
| `nslookup -type=SRV _ldap._tcp.dc._msdcs.company.local` | Проверка SRV-записи DC        |
| `ping 10.10.10.10`                                      | Проверка связности с DC       |
| `whoami`                                                | Проверка текущей учётки       |
| `gpupdate /force`                                       | Принудительное применение GPO |
| `gpresult /r`                                           | Список применённых GPO        |
| `Get-ADUser`, `Get-ADGroup`, `Add-ADGroupMember`        | Работа с AD через PowerShell  |

## Что запомнить для собеса

- **AD — это роль, а не сервер.** DC может быть и DNS, и файловым сервером.
- **OU ≠ группа.** OU — контейнер для структуры и GPO, группа — для прав.
- **AGDLP:** Accounts → Global → Domain Local → Permissions.
- **GPO привязывается к контейнеру** (сайт, домен, OU).
- **Вход в домен** = `sysdm.cpl` → Domain → `company.local`.
- **Учётка компьютера создаётся автоматически** при вводе в домен.
- **Диагностика входа:** DNS → часы → учётка → канал доверия.
