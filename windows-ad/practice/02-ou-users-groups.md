# 02. OU, пользователи, группы и схема AGDLP

## Задача

На готовом контроллере домена `company.local` (из практики 01) создать
структуру OU по подразделениям, завести пользователей, глобальные группы,
доменную локальную группу. Пройти полную схему AGDLP на реальной папке
с настройкой прав Share + NTFS и проверить эффективные права через
Effective Access.

## Что понадобилось

- **DC01** (Windows Server 2025) — поднят в практике 01
- **AD Users and Computers** (`dsa.msc`)
- **PowerShell** с модулем ActiveDirectory
- **Папка `C:\Shared`** на DC
- **Время:** ~1.5 часа

## Ход работы

### 1. Структура OU

В корне домена `company.local` создал три OU:

- `Отдел продаж`
- `Бухгалтерия`
- `IT`

В каждой — две подпапки: `Пользователи` и `Компьютеры`.
Дефолтные контейнеры (`Builtin`, `Computers`, `Users`, `Domain Controllers`)
не трогал — они системные.

### 2. Пользователи

Завёл по 2 пользователя в каждой OU:

| OU                        | Пользователи             |
| ------------------------- | ------------------------ |
| IT/Пользователи           | `ismirnov`, `avolkov`    |
| Отдел продаж/Пользователи | `ppetrov`, `ssidorova`   |
| Бухгалтерия/Пользователи  | `iivanova`, `kkuznetsov` |

При создании снимал галочку «Требовать смены пароля при следующем входе» —
иначе при каждом логине пришлось бы менять пароль.

### 3. Глобальные группы (G в AGDLP)

В каждой OU создал **глобальную группу безопасности**:

| OU           | Группа            | Область    | Тип          |
| ------------ | ----------------- | ---------- | ------------ |
| IT           | `GG_IT`           | Глобальная | Безопасность |
| Отдел продаж | `GG_Отдел_продаж` | Глобальная | Безопасность |
| Бухгалтерия  | `GG_Бухгалтерия`  | Глобальная | Безопасность |

В каждую положил по 2 пользователя из соответствующей OU.

### 4. Доменная локальная группа (DL в AGDLP)

Создал в OU `IT` группу `DL_Shared_RW`:

- **Область действия:** Локальная в домене (Domain Local)
- **Тип:** Безопасность

**Важно:** изначально по ошибке выбрал тип «Распространение» — права
NTFS так дать нельзя. Исправил на «Безопасность».

Добавил в `DL_Shared_RW` **глобальные группы**, не пользователей:

- `GG_IT`
- `GG_Отдел_продаж`

`GG_Бухгалтерия` **специально не добавлял** — она нужна для проверки,
что у бухгалтерии доступа нет.

### 5. Папка и права (P в AGDLP)

Создал `C:\Shared`, расшарил под именем `Shared`.

**Share Permissions:**
- `Everyone` → Change

**NTFS Permissions:**
1. Отключил наследование → преобразовал унаследованные в явные.
2. Удалил **обе** записи `COMPANY\Пользователи` (Domain Users) —
   это группа, в которую автоматически входят все пользователи домена.
3. Добавил `DL_Shared_RW` с правами **Modify**.

### 6. Проверка Effective Access

Свойства `C:\Shared` → Безопасность → Дополнительно → вкладка
«Действующие права доступа». Проверил для трёх пользователей:

| Пользователь             | Ожидаемо    | Получено      |
| ------------------------ | ----------- | ------------- |
| `ismirnov` (IT)          | Modify      | ✅ Modify      |
| `ppetrov` (Отдел продаж) | Modify      | ✅ Modify      |
| `iivanova` (Бухгалтерия) | нет доступа | ✅ нет доступа |

Цепочка прав для `ismirnov`:
`ismirnov → GG_IT → DL_Shared_RW → Modify на C:\Shared`


## Команды / настройки

### PowerShell — создание групп

```powershell
# Глобальная группа безопасности
New-ADGroup -Name "GG_IT" -GroupScope Global -GroupCategory Security `
  -Path "OU=IT,DC=company,DC=local"

# Доменная локальная группа безопасности
New-ADGroup -Name "DL_Shared_RW" -GroupScope DomainLocal -GroupCategory Security `
  -Path "OU=IT,DC=company,DC=local"
```

PowerShell — добавление участников
```powershell
# Пользователи в глобальные группы
Add-ADGroupMember -Identity "GG_IT" -Members ismirnov, avolkov
Add-ADGroupMember -Identity "GG_Отдел_продаж" -Members ppetrov, ssidorova
Add-ADGroupMember -Identity "GG_Бухгалтерия" -Members iivanova, kkuznetsov

# Глобальные группы в доменную локальную
Add-ADGroupMember -Identity "DL_Shared_RW" -Members GG_IT, GG_Отдел_продаж
```

PowerShell — проверки
```powershell
# Содержимое группы
Get-ADGroupMember -Identity "GG_IT" | Select name, SamAccountName

# Проверить objectClass — должны быть group, не user
Get-ADGroupMember -Identity "DL_Shared_RW" | Select name, objectClass

# Проверить DN пользователя
(Get-ADUser ismirnov).DistinguishedName
```

### Ключевые настройки
- Share Permissions: Everyone → Change

- NTFS: DL_Shared_RW → Modify

- Effective Access — вкладка «Действующие права доступа»

### Результат
- Три OU с подпапками Пользователи и Компьютеры.

- 6 пользователей в трёх OU.

- 3 глобальные группы безопасности с пользователями.

- 1 доменная локальная группа с глобальными группами внутри.

- Папка C:\Shared с корректными правами Share + NTFS.

- AGDLP работает: ismirnov и ppetrov получили Modify через
цепочку групп, iivanova доступа не имеет.

### Возможные ошибки:

1. `Add-` vs `Get-ADGroupMember`
Вводил `Add-ADGroupMember -Identity "GG_IT"` без `-Members` —
PowerShell уходил в интерактив и просил значение параметра.
Правило: `Add-` изменяет и не выводит, `Get-` читает и выводит.
Для проверки содержимого нужен `Get-`.

2. `-` (дефис) vs `_` (подчёркивание) в имени группы
Создал `DL-Shared_RW`, а в команде указывал `DL_Shared_RW` —
PowerShell не находил объект. Переименовал в `DL_Shared_RW`.
Правило: единообразие в именовании. Проверять точное имя через
`Get-ADGroup -Filter "Name -like 'DL*'"`.

3. Кириллица в DN ломает вывод PowerShell
`Format-List SamAccountName, DistinguishedName` показывал {} вместо
значений. Это глюк отображения, не пустые данные.
Решение: использовать `(Get-ADUser ismirnov).DistinguishedName`
или `-ExpandProperty`.

4. Тип группы: `Distribution` vs `Security`
Сначала выбрал «Распространение» — нельзя дать права NTFS.
Правило: для прав — только `Security`.

5. В NTFS надо удалять две записи `COMPANY\Пользователи`
Domain Users наследуется от родительской папки в двух видах —
«Чтение и выполнение» и «Особые». Обе надо удалить, иначе
все пользователи домена получат доступ.

6. `COMPANY\Пользователи` = Domain Users
Это встроенная группа, куда автоматически входят все пользователи
домена. Оставлять её в NTFS-правах = дать доступ всем.
Решение: удалить и заменить на точечную группу `DL_Shared_RW`.

### Что запомнить
- AGDLP: Accounts → Global → Domain Local → Permissions.

- DL-группа содержит глобальные группы, не пользователей.

- Права NTFS дают группе, не пользователю.

- Effective Access — инструмент проверки итоговых прав.

- Share + NTFS = пересечение. Работает минимум из двух.

- `-` ≠ `_` в именах объектов AD.

- `Add-` изменяет, `Get-` читает — правило командлетов PowerShell.
