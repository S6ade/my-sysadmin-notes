# Windows Server + Active Directory

## Зачем это нужно

AD — стандарт корпоративной инфраструктуры на Windows. Без него нет
централизованного управления пользователями, компьютерами и политиками.
На позиции sysadmin это база: в 80% компаний с Windows-парком AD есть.
На собесе спрашивают почти всегда.

## Ключевые понятия

- **AD (Active Directory)** — служба каталога. База данных объектов
  (пользователи, группы, компьютеры, принтеры) + протоколы доступа к ней
  + службы, которые её обслуживают. Это не «сервер», а роль на сервере.
- **Домен** — логическая граница AD: и область аутентификации,
  и пространство имён (например, `company.local`).
- **DC (Domain Controller, контроллер домена)** — сервер с ролью AD DS.
  Хранит копию базы каталога, обслуживает запросы аутентификации.
- **Лес (forest)** — верхний уровень иерархии AD. Дерево — набор доменов
  с общей схемой. Для джуна: один домен = один лес = норма.
- **DNS** — служба имён. Критическая зависимость AD: клиент находит DC
  именно через DNS-запросы (SRV-записи).
- **DHCP** — выдаёт клиентам IP, шлюз и адрес DNS-сервера. С AD связан
  через DNS: если выдаст «не тот» DNS, клиент в домен не войдёт.
- **OU (Organizational Unit)** — контейнер внутри домена. Для структуры,
  привязки GPO и делегирования прав.
- **GPO (Group Policy Object)** — набор правил, применяемых к объектам AD
  автоматически. Привязывается к контейнеру (сайт, домен, OU), не к группе.
- **Группа** — список членов. Используется для выдачи прав на ресурсы.
- **SAM** — локальная база учёток на конкретном Windows-компьютере.
- **NTDS.dit** — база каталога AD на контроллере домена.

## Как это устроено

### DC и база каталога

DC хранит базу каталога (файл `NTDS.dit`) и обслуживает запросы:
- аутентификация пользователей (Kerberos / NTLM)
- выдача списка групп и объектов
- распространение GPO

В лесу обычно несколько DC — для отказоустойчивости. Они реплицируют
базу между собой.

### Роль DNS в AD — критическая связка

Чтобы войти в домен, клиент должен **найти контроллер домена**.
Поиск идёт через DNS, конкретно через **SRV-записи** вида:
`_ldap._tcp.dc._msdcs.company.local`


Ответ — адрес DC. Если DNS не отвечает или не знает про зону
`company.local` — клиент не найдёт DC и **не войдёт в домен**.
Даже если учётка существует и DC жив.

Отсюда два следствия:

1. **DC обычно держит роль DNS на себе** — хранит зону `company.local`
   со всеми SRV-записями. Всё в одном месте, без внешних зависимостей.
2. **DHCP должен выдавать клиентам адрес DC как DNS-сервер.** Если выдаст
   DNS провайдера или роутера — клиент не найдёт домен.

Kerberos тоже завязан на DNS: имена принципалов (`user@company.local`)
должны резолвиться.

### Локальный vs доменный пользователь

|                    | Локальный        | Доменный          |
| ------------------ | ---------------- | ----------------- |
| Где хранится       | В SAM на этом ПК | В NTDS.dit на DC  |
| Область действия   | Только этот ПК   | Любой ПК в домене |
| Зайти с другого ПК | Нет              | Да                |

Информация о локальном пользователе лежит только на его машине.
Доменный пользователь хранится на контроллере домена — поэтому
его можно «предъявить» с любого компьютера в домене.

### OU vs группа — не путать

|              | OU                              | Группа                           |
| ------------ | ------------------------------- | -------------------------------- |
| Что это      | Контейнер (папка)               | Список членов                    |
| Зачем        | Структура + GPO + делегирование | Права доступа к ресурсам         |
| Что содержит | Пользователей, ПК, другие OU    | Пользователей, ПК, другие группы |
| Привязка GPO | Да                              | Нет                              |

Мнемоника: **OU — где объект живёт. Группа — что объект может.**

**Три функции OU:**
1. Структурирование объектов — иерархия по отделам, филиалам, функциям.
2. Привязка GPO — главная функция.
3. Делегирование прав администрирования.

**Важно:** дефолтный `Users` в корне домена — это **контейнер**, а не OU.
К контейнеру GPO привязывать не рекомендуется. Пользователей кладут
в свои OU — как в разделе `Пользователи` внутри OU отдела.

### GPO — что это и как работает

GPO — **набор правил и настроек**, применяемых к объектам AD автоматически.
Не протокол. Примеры: «запретить смену обоев», «включить заставку
с паролем», «запретить USB-накопители», «дисковые квоты».

Механика:

1. Создаёшь GPO.
2. **Привязываешь к контейнеру** — сайт, домен или **OU**.
3. Компьютеры и пользователи при входе/загрузке забирают настройки с DC.
4. Периодически (по умолчанию каждые 90 минут ± случайный сдвиг)
   переспрашивают изменения.

Ключевое: GPO распространяется **по структуре OU**, а не по членству
в группах. Есть исключения — Security Filtering и WMI Filtering,
но базовая механика — через OU.

**Порядок применения GPO (LSDOU):** Local → Site → Domain → OU.
Последняя выигрывает.

## Группы в AD

### Зачем нужны группы

Права дают **группе**, а не пользователю. Причины:

- **Масштабируемость.** 400 сотрудников — не выдашь права каждому вручную.
- **Принцип наименьших привилегий.** Ушёл сотрудник — убрал из группы.
- **Аудит.** Легче ответить «у кого доступ к папке X» — смотришь членство.

### Области действия групп (Group Scope)

| Область                               | Что может содержать                            | Где применяется       |
| ------------------------------------- | ---------------------------------------------- | --------------------- |
| **Глобальная (Global)**               | Пользователей и группы только из своего домена | В любом домене леса   |
| **Локальная в домене (Domain Local)** | Пользователей и группы из любого домена        | Только в своём домене |
| **Универсальная (Universal)**         | Пользователей и группы из любого домена леса   | В любом домене леса   |

В AGDLP: **G** = Global, **DL** = Domain Local, **U** = Universal
(в варианте AGUDLP).

### Типы групп

| Тип                                | Для чего                                     |
| ---------------------------------- | -------------------------------------------- |
| **Безопасность (Security)**        | Права доступа к ресурсам                     |
| **Распространение (Distribution)** | Рассылки (email-списки). Права давать нельзя |

**Мнемоника:** права даёшь — Security. Рассылки — Distribution.

### Вложенное членство групп

Группа может содержать **другую группу**. Это основа AGDLP.
Например, `DL_Shared_RW` содержит `GG_IT`, а `GG_IT` содержит
`ismirnov`. Пользователь получает права **через цепочку**.

## AGDLP — схема выдачи прав доступа

**AGDLP** — Accounts, Global groups, Domain Local groups, Permissions.

Цепочка:
`A (учётные записи) → G (глобальные группы) → DL (доменные локальные) → P (права)`

1. **A** — пользователи.
2. **G** — глобальные группы. Сюда кладут пользователей, обычно
   **по подразделению или функции**: `GG_IT`, `GG_Отдел_продаж`.
3. **DL** — доменные локальные группы. Сюда кладут **глобальные группы**,
   а не пользователей.
4. **P** — разрешения. Их дают **доменной локальной группе**, не G.

### Пример

Дать сотрудникам IT и Отдела продаж доступ к папке `\\DC01\Shared`.

1. `ismirnov`, `avolkov` → в `GG_IT`.
2. `ppetrov`, `ssidorova` → в `GG_Отдел_продаж`.
3. `GG_IT` и `GG_Отдел_продаж` → в `DL_Shared_RW`.
4. `DL_Shared_RW` → Modify на папке `C:\Shared` (NTFS).

Результат:
- `ismirnov` — доступ через `GG_IT` → `DL_Shared_RW`.
- `ppetrov` — доступ через `GG_Отдел_продаж` → `DL_Shared_RW`.
- `iivanova` (в `GG_Бухгалтерия`, которой нет в DL) — **нет доступа**.

### Зачем нужна прослойка DL

1. **Масштабируемость.** Управление доступом в одном месте.
2. **Мультидоменный лес.** DL может содержать G из разных доменов.
3. **Наименьшие привилегии.** Убрал из G — доступ пропал везде.

### Варианты схемы

- **AGLP** — без DL, права дают G. Работает только в одном домене.
- **AGDLP** — стандарт для одного домена.
- **AGUDLP** — с универсальной группой. Для мультидоменного леса.

## Права доступа: Share vs NTFS

В Windows **два уровня прав**, и они **умножаются** (работает
наименьшее из двух):

| Уровень               | Где настраивается             | Что регулирует            |
| --------------------- | ----------------------------- | ------------------------- |
| **Share Permissions** | Свойства папки → Доступ       | Сетевой доступ к шаре     |
| **NTFS Permissions**  | Свойства папки → Безопасность | Доступ к файловой системе |

**Эффективные права = пересечение Share и NTFS.**

Пример: на шаре `Everyone Change`, на NTFS `DL_Shared_RW Modify`.
Пользователь из `DL_Shared_RW` получит **Modify** (минимум из двух).

**Практика в проде:**
- **Share** — обычно `Everyone Change` или сужено до группы.
- **NTFS** — тонкая настройка через группы по AGDLP.

### Уровни NTFS-прав

| Уровень          | Что позволяет                     |
| ---------------- | --------------------------------- |
| **Read**         | Смотреть, открывать, читать       |
| **Modify**       | Read + писать, изменять, удалять  |
| **Full Control** | Modify + менять права и владельца |

### Effective Access (Действующие права доступа)

Инструмент Windows, который **считает итоговые права** пользователя
с учётом:
- всех его групп (прямое членство);
- вложенного членства (группы в группах);
- запрещающих правил (Deny);
- наследования от родительских папок.

**Где:** Свойства папки → Безопасность → Дополнительно → вкладка
«Действующие права доступа».

**Зачем:** ответить на вопрос «Почему у Пети нет доступа к папке?».
Смотришь Effective Access и видишь, какие группы дают доступ
и какие запрещают.

## Что важно не путать

- **AD — это роль, а не сервер.** Один сервер может быть DC, DNS,
  файловым сервером одновременно.
- **OU ≠ группа.** OU — контейнер, группа — список для прав.
- **GPO цепляется к OU, не к группе.** Область действия — по структуре.
- **DNS — не «связан» с AD, а критически зависим.** AD без DNS не работает.
- **DHCP не обязателен для AD**, но нужен, чтобы клиенты получали
  правильный DNS автоматически.
- **Права дают группе, не пользователю.** Пользователь получает
  через членство.
- **DL-группа содержит G-группы, а не пользователей.** Это и есть AGDLP.
- **Security vs Distribution.** Права дают только Security-группе.
- **Share и NTFS — два разных уровня прав.** Эффективные = минимум из двух.
- **`-` и `_` в именах групп — разные символы.** `DL-Shared` ≠ `DL_Shared`.
